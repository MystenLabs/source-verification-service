# Trustless Source Verification Attestations for Sui Packages

This package provides on-chain [attestations][atts] stating that a particular
source package compiles to the bytecode at a particular on-chain address.

[atts]: https://www.moveregistry.com/package/@mysten/attestations

Note that this does not imply anything about the correctness of the software,
only that the on-chain bytecode and the linked source code match.

Unlike other source verification systems, you do not have to trust the party
that performs or stores the verification --- barring an on-chain package
upgrade, it is impossible for anybody to produce an
`Attestation<SourceVerification>` for a package without successfully running
`sui client verify-source` on it first.

## Why should I trust source verification attestations?

Source verification attestations can only be produced by a [Nautilus][nautilus]
enclave that is running the specific software stack defined by this package.
That software will only sign off on creating the attestation after successfully
running [`sui client verify-source`][sui-verif] on the source package, which compiles it
using an official `sui` release binary and compares the generated bytecode with
the on-chain bytecode for the package.

[nautilus]: https://docs.sui.io/sui-stack/nautilus/nautilus-overview
[sui-verif]: https://docs.sui.io/develop/manage-packages/source-verification

The verification checks:
 - **The bytecode of the package**: the bytecode produced by `sui move build`
   is identical to the on-chain bytecode for the package.

 - **The addresses of the dependencies**: the dependencies listed in the
   on-chain linkage table are the same versions as those used when rebuilding the package

Verification does **not** check:
 - **Macros**: macros have no on-chain representation, so it is impossible to
   determine whether they have changed since the package was published. Use
   macros from dependencies with caution.

 - **Documentation**: likewise, comments and other documentation are not
   present on chain, so they are not verified.

 - **The source code of the dependencies**: only the source code defined in the
   package itself is verified; the dependencies' source code should be verified
   separately.

The attestation itself records the specific commit SHA of the verified source
code, along with the hash of the `sui` binary that was used to rebuild the
source code.

It is technically possible to create multiple git commits with the same SHA
(git uses SHA-1 by default which is not cryptographically strong); the
attestations also include a blake2b256 hash of the verified source code, which
can be recomputed from the source using the source-hash tool contained in this
repository.

## How can I verify my source code?

Because Nautilus guarantees the integrity of a source verification, attestation
is permissionless: anyone with access to an AWS Nitro Enclave can create a
source verification attestation for any package.

The first step is to make sure that your source code does actually verify.
Install the latest `sui` binary and run `sui client verify-source` on your
source package. Follow the instructions [here][verif-troubleshoot] to create a
version that cleanly verifies.

[verif-troubleshoot]: https://docs.sui.io/develop/manage-packages/source-verification#when-verification-fails

Currently, mvr is not operating a service to generate source verification
attestations, so if you want to produce an attestation for your package, you
will need to build and run the source verification on an AWS Nitro enclave
yourself. See TODO for detailed instructions.
